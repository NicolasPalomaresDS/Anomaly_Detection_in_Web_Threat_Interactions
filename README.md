# Cybersecurity: Anomaly Detection in Suspicious Web Threat Interactions Using Machine Learning

### **[Interactive demo (web page)](https://npds.net.ar/threat_detector.html)**

The present project is aimed at detecting suspicious activities and potential attack attempts in web traffic interactions. It follows a systematic approach:

> **Baseline Model**: A simple statistical detector using the Interquartile Range (IQR) method establishes the minimum performance threshold. This baseline identifies extreme outliers based on traffic volume (bytes transferred).

> **Advanced Model**: An Isolation Forest algorithm captures multidimensional patterns that the baseline cannot detect, considering multiple features simultaneously (bytes in, bytes out, hour of day and the bytes out/in ratio).

> **Comparative Analysis**: Both models are evaluated on the same chronological test set. The comparison looks at how many events each one flags and where they agree, and the Silhouette Score measures how well the Isolation Forest separates flagged from normal traffic.

The data was generated by monitoring traffic to a production web server, using various detection rules to identify anomalous patterns. **Every record was already flagged as suspicious**, so the models learn what is unusual *within* that traffic, not what is malicious.

### Results
The dataset has 282 records, split chronologically into 217 for training and 65 for testing.

| | Baseline (IQR) | Isolation Forest |
|---|---|---|
| Features | bytes in, bytes out | bytes in, bytes out, hour, bytes ratio |
| Flagged (of 65 test records) | 11 (16.92%) | 19 (29.23%) |
| Flagged by both | 11 | 11 |
| Flagged only by this model | 0 | 8 |

* Agreement between both models: 87.69%.
* Silhouette Score of the Isolation Forest split: 0.5433.

The Isolation Forest flags every record the baseline flags plus 8 more that look ordinary on bytes alone. Flagging more events does not by itself mean it is more accurate, because the dataset has no ground-truth attack labels. A tiered strategy fits both results: events flagged by both models are high-priority alerts, and events flagged only by the Isolation Forest are routed for analyst review.

### Limitations
* **Small dataset**: 282 records, of which 217 are used for training.
* **No ground truth**: every record was already labelled as suspicious by detection rules, so precision and recall cannot be measured. The Silhouette Score measures cluster separation, not accuracy.
* **"Anomaly" is not "attack"**: it means unusual compared with this already-suspicious traffic.
* **Narrow time window**: the records span only 23:00 to 10:00 UTC on 25-26 April 2024. The model has no information about other hours.
* **Threshold**: the model uses `contamination='auto'` (score threshold 0.5), so the share of flagged records is not an estimate of the real attack rate.
* **Unused columns**: `duration_seconds` is constant (600 s) and the remaining columns have one or few distinct values, so they were left out of the model.

### Interactive page
The trained pipeline runs directly in the browser, with no backend: nothing the user types is sent anywhere.

1. `scripts/export_model.py` converts `pipeline/pipeline.joblib` (scaler and Isolation Forest) into `model.json`, and checks that the exported model reproduces the scikit-learn scores.
2. The static page (`anomaly_detector.html`, `detector_styles.css` and `app.js`) loads `model.json` and scores each connection with the same algorithm as scikit-learn.

To regenerate the exported model after retraining:

```bash
python scripts/export_model.py pipeline/pipeline.joblib model.json
```

To try the page locally, serve the folder that contains the page and `model.json` (opening the file directly does not work, because browsers block `fetch` on local files):

```bash
python -m http.server 8080
```

### Directory Structure
* `app.py`: Streamlit application script.
* `notebook.ipynb`: Jupyter Notebook with the code.
* `requirements.txt`: Required libraries for notebook execution.
* `dataset/`: Dataset in CSV format.
* `pipeline/`: Directory with the exported pipeline (scaler and Isolation Forest model).
* `model.json`: Pipeline exported for the web page.
* `scripts/`: Custom Python scripts.
    - `scripts/df_summary.py`: For a complete dataset summary generation.
    - `scripts/baseline_model.py`: Script with baseline model class.
    - `scripts/export_model.py`: Exports the pipeline to `model.json`.

### Requirements
You can install the necessary libraries by running the following command:

```bash
# Install dependencies
pip install "pandas>=2.0.0" \
            "numpy>=1.24.0" \
            "scikit-learn>=1.3.0" \
            "matplotlib>=3.7.0" \
            "seaborn>=0.12.0" \
            "matplotlib-venn>=0.11.0" \
            "jupyter>=1.0.0" \
            "ipython>=8.12.0" \
            "joblib>=1.3.0"
```

Alternatively, you can run the `requirements.txt` included in the project using the following command: `pip install -r requirements.txt`. It is also recommended to create a virtual environment for dependencies management:

```bash
# Create virtual environment
python -m venv venv

# Activate
source venv/bin/activate     # Linux/macOS
venv\Scripts\activate        # Windows
```

Once the virtual environment is configured, continue with the packages installation. The Streamlit version additionally needs `streamlit`.
